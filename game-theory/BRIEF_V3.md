# v3 画面标准（模板作者必读，优先于 BRIEF.md 的视觉部分）

用户对 v2 的评价是："太像 PPT 了，没有任何优雅高级感。" v3 的目标是做到参考片《进化论》的水准：**画面是一个有光、有景深、有质感的"场景"，而不是一页排版。**

## 一句话标准
**不要框。** 不用 panel、卡片、圆角矩形、表格线、按钮、图标徽章、项目符号列表，也不用顶部进度条。需要"结构"时，靠**位置、光、大小、景深**来表达，不靠边框。

## 视觉语言（用 `window.L`，定义在 web/look.js）
- **材质是汉字本身**：用 `L.glyph(ch,x,y,size,color,alpha,{blur,glow})` 画成千上万个字形粒子。离镜头远的字小、暗、模糊（blur 2–6），近的字大、亮、清晰，这样就有景深。例：用"默/招"两个字组成 100 对囚徒；用"鹰/鸽"组成种群；用"店"字排成一条街。
- **光负责强调**：`L.light(x,y,r,color,alpha)` 是加色混合的柔光。重点处放一团光（最优解用绿光 `OK`，均衡或结论用 ember/gold 暖光，危险或背叛用暗红）。不要用色块或底色高亮。
- **字**：展示字统一用 `L.serif(str,x,y,{size,glow,alpha,reveal,highlight,hiColor})`，它会让字从模糊到清晰、从左到右逐字浮现（reveal 0..1）。主字号 56–92，次级 36–44，标签最小 26。实时数字放在左上角那一行 mono HUD 里：`L.hud([{label,value,color,glow}], {alpha})`。
- **氛围**：`L.field(lt,{n,chars,seed,alpha,color})` 是缓慢漂移的一层淡字场，可以用当前话题的字做背景质感，alpha 保持在 0.06–0.16。
- **颜色**：背景由运行时按集数调色，模板不要铺背景。前景颜色只用这几种：
  `INK '#efe9dc'`、`DIM 'rgba(239,233,220,0.45)'`、`GOLD '#e9c47a'`（甲、己方）、`TEAL '#7fd8cb'`（乙、对方）、`EMBER '#ff9f5a'`（强调、均衡、结论）、`OK '#9fe0a0'`（最优、正确）、`RED '#e0705f'`（损失、背叛）。强调色请用 `L.accent(T.TL, t)`。
- **线**：如果非要用线，只能是 1–1.5px 两端渐隐的"光线"（linear gradient，两端 alpha 为 0），或者由点和字排成的线。
- **运动**：慢。元素用 0.8–1.6 s 从模糊到清晰地淡入；镜头式的缓慢推进或漂移可以用（整体 scale 每秒变化不超过 1%）。不要弹跳，不要闪烁，同一时刻只有一个焦点在动。
- **构图**：一个中心，大面积留白（暗）。内容放在 y 150–900。左上角 y≈86 是 HUD 的位置。
- 运行时每帧最后会做全屏 bloom，所以亮的字会自然发光。不要自己再叠一层大面积的 glow。

## 没有字幕（v4 起的硬规则）
画面上**不会出现字幕**，也就是任何压在画面底部、跟着画面一句句换的文字。这是用户明确提出的要求，流水线会强制执行：
- 脚本里的一段（beat）只有两种。**文字屏**（`line`、`remember`、`question` 等）承载句子，一句一屏，占满整个画面。**画面屏**（其余所有模板）不带 `lines`。
- 画面屏按自己的时钟播放：每个 step 有 `dur`（持续秒数），没有 step 的画面用 `hold`。模板只根据 `api.steps` 和 `api.dur` 安排节奏，不要依赖 `api.beat.lines`，画面屏里它是空的。
- 观众在画面里必须读到的信息，写成画面内的标签，包括 step 的 `label`/`note`、条目的 `desc`、HUD 数字，字要短（通常 2–12 个字）。完整的句子放在画面前后的文字屏里。一般是先用文字屏交代要看什么，再放画面，最后用文字屏给结论。
- 一个解释分前后两半时，把画面拆成 ref 链，中间插入文字屏，例如 dough 的 1928/1950、rounds 的倒推和 KMRW。
- `gen_timeline.py` 在脚本写了 `"subtitles": false` 时，发现画面屏里带 `lines` 就直接报错，拒绝生成时间轴。

## "卡片 / 列表 / 对比"这类内容怎么改
- **cards 或 list（几个要点）**：改成几个大号衬线关键词，排在一条缓慢的弧线上或几层景深里，依次被光"点亮"。点亮的是当前这一个，已经讲过的退到远处并变暗、变模糊。desc 用 36–40px 的 DIM 小字放在关键词下方，只在它被点亮时出现。不要画编号圆圈，可以在关键词上方用 26px 的 mono 标 `01`、`02`。
- **compare（左右对比）**：画面中间是一条竖的光线，左右两边各一个大号关键词，下面是它的要点。当前在讲的那边更亮、更清晰，另一边退到景深里。
- **timeline**：一条横向的光线，年份用 mono，事件用衬线字，镜头沿着线缓慢横移。
- **tree（博弈树）**：节点是发光的点，边是渐隐的光线，走过的路径被一束光沿着描出来，没选的枝暗下去。
- **模拟（sim_*）**：由字形粒子组成的"种群、人群、街道"，数字放进 HUD；最后的结论数字要大（160–220px 的衬线字，用 EMBER 发光），这时其余东西变暗。

## 技术规则（与 BRIEF.md 相同）
- 每一帧都是 t 的纯函数。禁止 Math.random、Date、rAF 和跨帧状态（缓存贴图可以），随机数用 `K.rng(seed)`。
- 时间一律相对 `api.line(k)`、`api.steps`、`api.dur`、`api.phases`。
- ref 链：链内后一个 beat 的第一帧要和前一个 beat 的最后一帧一致。
- 单帧绘制 < 40ms。`L.glyph` 有贴图缓存，但 size 和 blur 会被量化，**不要**每帧生成连续变化的 blur 值（会把缓存撑爆）。blur 取整数，size 取偶数。
- 只写自己负责的文件 `web/templates/v3_*.js`（已在 index.html 中加载，位于 v3.js 之后，同名注册会覆盖旧模板）。不改其他文件，不 git commit。
- 参考 `web/templates/v3.js`（line、remember、question、matrix、sim_prisoners 已经按这个标准做好了，照它的手法来）。参考片的静帧在 `$BOSS/f0*.png`（高清的是 hi_*.png），先看 6–8 张。
- 预览：`node pipeline/render.mjs still <秒> [--out build/stills_<你的名字>]`，也可以 `sheet <beat_id> --n 12 --out ...`。时间点见 `build/timeline.json`。用 Read 看 PNG，**至少迭代 3 轮**，每轮都要对照参考片自问："这像一页 PPT 吗？"
