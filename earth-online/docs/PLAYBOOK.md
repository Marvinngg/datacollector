# 用 Claude Code 做一部代码短片：方法手册

这部片子是一个人和一组 AI Agent 协作完成的。本文把流程整理成可以重复的步骤，同事可以照着做自己的片子。本目录下的引擎、流水线和音频代码可以直接复用，需要重写的只有剧本、台词和各幕画面。

## 角色与分工

| 阶段 | 谁来做 | 产出 |
|---|---|---|
| 1. 聊想法 | 你 + 主会话 | 你要表达的核心感受、基调、受众 |
| 2. 调研 | 3 个调研 Agent 并行 | `research/notes.md`：同题材别人怎么讲、经典作品的叙事手法、克制表达的写作守则 |
| 3. 剧本 | 主会话起草，你拍板 | `script/vN.md`：分镜 + 旁白 + 画面文字 |
| 4. 制作规则 | 主会话 | `BRIEF.md`（共用组件、场景交接状态、音效 cue 词表、文件归属）和引擎 |
| 5. 并行制作 | 画面 Agent ×3、配乐 Agent、配音 Agent | `web/scenes/*.js`、`pipeline/audio/*`、`lines.json` |
| 6. 审片 | 审片 Agent | 按严重程度排序的问题清单 |
| 7. 返修 | 把问题交回原作者 Agent（它们有上下文） | 修改后的场景 |
| 8. 总装 | `bash pipeline/make.sh` | `release/*.mp4` |

这次用了 10 个 Agent（含主会话）。3 个调研 Agent 大约各用 3–5 分钟；各幕画面每位作者约 20 分钟；配乐约 50 分钟。

## 每一步的要点

### 1. 聊想法：先对齐，不要急着写

- 先复述你理解的内容，再提 3–4 个具体问题：真正想表达什么、有没有转折点、情绪基调、给谁看。
- 用户的原话最重要。这次第一、二版剧本被否，就是因为"替用户加戏"、表达太满。

### 2. 调研：先找方法，再动笔

- 并行派 3 个 Agent：一个查同题材在中文互联网上的说法和陈词滥调，一个查经典作品的叙事手法，一个查克制短片的写作方法（结构、旁白、字数节奏）。
- 让它们最后给出"值得借鉴 / 应当避免"的判断和写作守则，而不只是摘抄。

### 3. 剧本：画面讲故事，旁白只是心里话

- 这次定稿的写法是"任务日志"：故事靠屏幕上的界面文字推进，旁白口语、带点自嘲，不讲道理。
- 结尾用一个回环（片中的 AI 队伍接到的任务，就是做出这部片子），深度靠回扣和留白，不靠总结语。

### 4. 制作规则：并行不打架的关键

- **时间轴由配音生成**，场景里一律用相对时间（`E.lineLocal`），禁止写死绝对秒数。
- **每一帧是时间的纯函数**，禁止用随机数、`Date` 和跨帧状态，这样才能多进程并行渲染，也能乱序重渲。
- **定义场景交接的"标准状态"**（同一个镜头、同样的迷雾和 HUD），相邻场景的作者各自对齐这个状态，做到逐像素无缝。
- **一个文件只归一位 Agent**，共用能力只放进引擎，由主会话统一维护。
- **预先定好音效 cue 词表**，画面作者声明 cue，配乐 Agent 按 cue 做声音，两边不必互相等待。

### 5. 并行制作：给 Agent 的任务模板

每个画面 Agent 的提示词结构如下（原文可以参考本仓库提交历史里的 `BRIEF.md` 和各场景文件头）：

```
你是《片名》的动态设计师，负责 <场景 id>。只写 <文件>。
开工前必读：BRIEF.md、script/vN.md、web/engine.js、pipeline/lines.json、build/timeline.json。
不要读取本目录以外的文件；不要改 engine.js；不要 git commit。
起始状态：<交接状态>。结束状态：<交接状态>。
<逐段写清：画面里发生什么、对齐哪一句旁白、要发哪些 cue>
要求：时间相对 E.lineLocal；质量对标顶级动态设计工作室；底部 170px 留给字幕；单帧 < 60ms。
自检：用 render.mjs sheet/still 出图并用 Read 看 PNG，至少迭代 3 轮，检查首尾帧与交接状态一致。
完成后汇报：实现了什么、设计决定、已知问题、看过的关键帧。
```

配乐 Agent 要写清每一段的情绪和锚点（哪一句旁白时静音、哪个 cue 上落和弦），并要求它用频谱图、响度、单声道兼容性来自检。

配音 Agent 用 ASR 把合成语音转回文字、按拼音比对来找读错的字，用基频分析来筛男声和女声。

### 6. 审片：专门派一个 Agent 挑毛病

让它只审不改，对每句旁白的中点和每个场景交接点出静帧，按"必须改 / 建议改 / 可选"给出清单，并写明时间点和改法。这次它找出了字幕叠字、结尾停留太短、余额数字倒跳、画面过暗等问题。

### 7. 人必须亲耳听、亲眼看

Agent 听不到声音，只能靠频谱、响度和 ASR 判断。**音色是否自然、口音是否地道，一定要人来听。**这次用户听完指出配音"不是正统中国人说中文"，于是换了引擎，做法是生成几段试听样本，由用户挑选。

## 踩过的坑

- **分享文件要放在不被 git 忽略的目录**。仓库根目录的 `.gitignore` 忽略了 `out/`，第一次给出的下载链接是 404，所以成片改放 `release/`。推送后要用 `git ls-tree origin/<分支>` 确认远程真的有这个文件。
- **不要为了卡时长牺牲语气**。把语速提到每秒 5 个字，听起来就不放松了；总时长宁可长一点。
- **Hugging Face 在部分网络环境不可用**。模型一律从 GitHub Releases（sherpa-onnx）获取。
- **无 GPU 的无头 Chromium 很慢**，一帧约 80ms。要按多进程分段渲染来规划时间，并把重的静态图层缓存到离屏画布。
